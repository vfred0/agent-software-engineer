== Formularios Dinámicos

Los formularios dinámicos se implementan mediante:
1. Componentes de formulario (`app-input`, `app-select`, `app-datepicker`, etc.) que usan `formGroupKey` para bindear al `FormGroup` padre.
2. Clase `DynamicControlHandler<T>` (en `shared/components/forms/core/dynamic-control-handler.ts`) que maneja el `FormControl`, validaciones y estado.
3. Validaciones centralizadas en `shared/components/forms/core/validations.ts` y patrones en `patterns.ts`.
4. Interfaz `CustomValidator` para validadores con mensaje personalizado.

=== Clase `DynamicControlHandler<T>` (`core/dynamic-control-handler.ts`)

Maneja la creación, validación y estado de un `FormControl` dentro de un `FormGroup` padre.

[source, typescript]
----
export class DynamicControlHandler<T = unknown> {
  control: FormControl = new FormControl();
  patternConfig: PatternConfig | null = null;
  pendingValidations: Signal<string[]> = signal([]);

  // Crea control con validadores
  createInput(parentForm: FormGroup, key: string, validators: CustomValidator[], injector: Injector, validateOnChange = false);

  // Crea control para tipos genéricos (select, datepicker, etc.)
  createToGenericControl(control: FormGroup, key: string, required: boolean);

  // Crea control sin validadores
  createInputWithoutValidators(control: FormGroup, key: string);

  // Establece valor por defecto
  defaultValue(value: T);

  // Verifica si el control es válido según validaciones pendientes
  isFormControlValid(): boolean;

  // Agrega validador dinámicamente
  addValidators(validatorFn: ValidatorFn);
}
----

=== `CustomValidator` (`core/models.ts`)

Interfaz para validadores con mensaje personalizado:

[source, typescript]
----
export interface CustomValidator {
  validator: ValidatorFn;  // Función validadora de Angular
  message?: string;      // Mensaje de error personalizado
}

export interface ValidatorConfig {
  required: boolean;
  minLength: number;
  maxLength: number;
  customValidators: CustomValidator;
}
----

=== `ValidatorBuilder` (`core/validations.ts`)

Construye un array de `CustomValidator[]` basado en configuración:

[source, typescript]
----
export class ValidatorBuilder {
  static build(config: ValidatorConfig): CustomValidator[] {
    const validators: CustomValidator[] = [];

    if (config.required) {
      validators.push({ validator: Validators.required, message: 'Campo requerido' });
    }
    if (config.minLength > 0) {
      validators.push({ validator: Validators.minLength(config.minLength), message: `Mínimo ${config.minLength} caracteres` });
    }
    if (config.maxLength > 0) {
      validators.push({ validator: Validators.maxLength(config.maxLength), message: `Máximo ${config.maxLength} caracteres` });
    }
    if (config.customValidators) {
      validators.push(config.customValidators);
    }
    return validators;
  }
}
----

=== `PatternExtractor` y `PatternFilter` (`core/patterns.ts`)

Extraen y filtran caracteres inválidos según el patrón del validador:

[source, typescript]
----
// Extrae configuración de patrón de un CustomValidator
export class PatternExtractor {
  static extract(validators: CustomValidator[]): PatternConfig | null {
    for (const v of validators) {
      const testControl = new FormControl('!!!');
      const result = v.validator(testControl);
      if (result?.['pattern']) {
        const requiredPattern = result['pattern'].requiredPattern;
        // Extrae caracteres permitidos
        return { regex: new RegExp(...), restRegex: new RegExp(...), message: v.message! };
      }
    }
    return null;
  }
}

// Filtra caracteres inválidos en tiempo real
export class PatternFilter {
  constructor(private control: FormControl, private patternConfig: PatternConfig) {
    this.setup(); // Suscribe a valueChanges
  }

  get hasInvalidChar(): Signal<boolean> {
    return this.invalidCharDetected.asReadonly();
  }

  private setup() {
    this.control.valueChanges.subscribe((value) => {
      if (!value) return;
      const filtered = value.replace(this.patternConfig.restRegex, '');
      if (value !== filtered) {
        this.invalidCharDetected.set(true);
        // Actualiza el control con valor filtrado
        queueMicrotask(() => {
          this.control.setValue(filtered, { emitEvent: true });
        });
      }
    });
  }
}
----

== Componentes Compartidos

=== Catálogo de Componentes de Formulario (`shared/components/forms/`)

Todos los componentes de formulario usan `formGroupKey` para vincularse al `FormGroup` padre mediante `ControlContainer`.

==== `app-input` (`input.component.ts`)

Inputs:
- `formGroupKey`: string (required) - Clave en el FormGroup padre.
- `label`: string - Etiqueta del campo.
- `type`: 'text' | 'password' | 'number' | 'phone' | 'email' | 'cedula_ruc' | 'textarea' (default: 'text').
- `validationType`: 'alpha' | 'alphanumeric' | 'phone' | 'email' | 'cedula_ruc' | 'paragraph' | null.
- `placeholder`: string.
- `required`: boolean (default: false).
- `minLength`: number (default: 1).
- `maxLength`: number (default: 100).
- `validators`: CustomValidator (validadores adicionales).
- `prefixIcon`: string (ícono Kobiq).
- `min`: number (para type='number').
- `max`: number (para type='number').
- `withThousandSeparator`: boolean (para type='number').
- `integer`: boolean (para type='number').
- `showStepper`: boolean (para type='number').

Validación automática por `validationType`:
- `alpha`: Solo letras (regex: `/[^a-zA-ZáéíóúÁÉÍÓÚñÑ\s]/g`), mensaje: 'Solo se permiten letras'.
- `alphanumeric`: Letras y números (regex: `/[^a-zA-Z0-9áéíóúÁÉÍÓÚñÑ\s]/g`).
- `phone`: Solo números, patrón: `/^(09\d{8}|0[2-8]\d{7})$/`, maxlength=10.
- `cedula_ruc`: Solo números, patrón: `/^(\d{10}|\d{13})$/`, maxlength=13.
- `paragraph`: Letras, números y signos de puntuación (regex específico).
- `email`: Validators.email de Angular.
- `number`: Valida min/max.

Comportamiento:
- Filtra caracteres inválidos en tiempo real y muestra mensaje temporal.
- Convierte a TitleCase para `alpha`/`alphanumeric`/`text`.
- Primera letra en mayúscula para `paragraph`.
- Usa `KbqTooltip` manual para mostrar errores.

==== `app-select` (`select.component.ts`)

Inputs:
- `formGroupKey`: string (required).
- `label`: string.
- `options`: Option<T, D>[] (model, puede ser extendible).
- `multiple`: boolean (default: false) - Selección múltiple.
- `searchable`: boolean (default: false) - Búsqueda dentro del select.
- `allowNewOption`: boolean (default: false) - Permite agregar nuevas opciones.
- `loading`: boolean (default: false) - Muestra skeleton mientras carga.
- `icon`: string (default: 'gear').

Outputs:
- `selectChange`: Emite la opción seleccionada (o array para multiple).

Variantes:
- *Selección simple*: Emite `Option<T> | null`.
- *Selección múltiple*: Emite `Option<T>[]`, muestra checkboxes.
- *Con búsqueda*: Incluye campo de búsqueda con resaltado (`KbqHighlightModule`).
- *Con grupos*: Soporta `optgroups` si las options tienen `options: Option<T>[]`.

Comportamiento:
- Al inicializar, selecciona la primera opción si el control está vacío.
- En modo `allowNewOption`, muestra un footer con input y botón para agregar.

==== `app-button` (`button.component.ts`)

Inputs:
- `variant`: 'default' | 'trash' | 'edit' (default: 'default').
- `icon`: string (default: 'floppy-disk').
- `iconPosition`: 'start' | 'end' (default: 'start').
- `color`: string (default: 'contrast-fade').
- `text`: string (default: 'Guardar').

Confirmación:

Se divide en 2 filas (BEM: `filter-bar__top-row`, `filter-bar__bottom-row`):

1. *Top Row*: Búsqueda + botón de acción + (en mobile) botón de filtros + paginación.

==== Filtros (`KbqFilterBar`)

- Recibe `filter` (un `KbqFilter` creado con `createFilter()`).
- Convierte cambios a `SearchCriteria.filters` mediante `mapFilters()`:

[source, typescript]
----
protected onFilterChange(kbqFilter: KbqFilter | unknown): void {
  const castKbqFilter = kbqFilter as KbqFilter;
  let filters = mapFilters(castKbqFilter);  // a formato plano

  // Aplica valores por defecto si el usuario vacía un filtro
  filters.forEach((filter, index) => {
    if (filter.value.length === 0) {
      const defaultFilters = mapFilters(this.filter()!.default);
      const defaultFilter = defaultFilters.find(f => f.id === filter.id);
      if (defaultFilter) filters[index].value = defaultFilter.value;
    }
  });

  // Filtra por visibilidad (FilterRule)
  filters = filters.filter(f => this.isFilterVisible(f.id));
  this.updateSearchCriteria({ filters });
}
----

==== Visibilidad de Filtros (`FilterRule`)

Las reglas en `filter.rules` controlan qué filtros mostrar:

[source, typescript]
----
protected isFilterVisible(filterType: string): boolean {
  const rule = this.filterRules()?.find(r => r.filter === filterType);
  return !rule || rule.visible;  // si no hay regla, visible
}

private updateVisibility(kbqFilter: KbqFilter): void {
  this.filterRules()?.forEach(rule => {
    if (rule.dependsOn?.filter) {
      const pipe = kbqFilter.pipes.find(p => p.filterName === rule.dependsOn.filter);
      const selectedValues = pipe!.value as KbqPipe[];
      rule.visible = selectedValues?.length === 1 && 
                    rule.dependsOn.values.includes(selectedValues[0].id as string);
    }
  });
}
----

==== `SearchCriteriaService` (Puente)

El filter-bar actualiza el `SearchCriteriaService` que está inyectado en el explorador:

[source, typescript]
----
private updateSearchCriteria(updates: Partial<SearchCriteria>): void {
  this.searchCriteria.update(current => ({
    ...current,       // preserva query, filters, page existentes
    ...updates,      // sobreescribe solo lo que cambió
  }));
  this.searchCriteriaService.value = this.searchCriteria(); // notifica al servicio
}

==== `date-badge.component.ts`

Input: `value` (DateTime), `label` (string opcional), `color` (default: 'fade-contrast'), `withRelativeTime` (boolean, default: true).

Comportamiento: Muestra la fecha formateada. Si `withRelativeTime=true`, muestra tiempo relativo (ej. "hace 3 horas") y el tooltip muestra la fecha completa. Si `withRelativeTime=false`, muestra la fecha formateada directamente.

Usa `ParseDate` de `core/utils/parse-date` para formateo.

[source, typescript]
----
import { ParseDate } from '@core/utils/parse-date';
import { DateTime } from 'luxon';

export class DateBadgeComponent {
  value = input<DateTime>(DateTime.now());
  label = input('');
  color = input('fade-contrast');
  withRelativeTime = input(true);

  displayDate = computed(() => {
    if (this.withRelativeTime()) {
      return ParseDate.toRelativeTime(this.value()); // ej. "hace 3 horas"
    }
    return ParseDate.toFormat(this.value()); // ej. "05/05/2026"
  });

  tooltip = computed(() => {
    if (this.withRelativeTime()) {
      return ParseDate.toFormat(this.value()); // tooltip muestra fecha completa
    }
    return ParseDate.toRelativeTime(this.value()); // tooltip muestra tiempo relativo
  });
}
----

==== `pagination.component.ts`

Input: `totalPages` (number, default: 10), `page` (model, default: 1).

Comportamiento: Muestra botones de navegación de página. Valida que la página esté entre 1 y `totalPages`. Usa `clamp()` para limitar el valor. Emite `pageChange` cuando cambia.

[source, typescript]
----
export class PaginationComponent {
  totalPages = input<number>(10);
  page = model<number>(1);

  canGoBack = computed(() => this.page() > 1);
  canGoForward = computed(() => this.page() < this.totalPages());

  navigateTo(newPage: number): void {
    this.page.set(this.clamp(newPage, 1, this.totalPages()));
  }

  private clamp(value: number, min: number, max: number): number {
    return Math.max(min, Math.min(max, value));
  }
}
----

==== `loader.component.ts`

No se encontró un archivo `loader.component.ts` en el proyecto. En su lugar, se usan directamente los skeletons de Kobiq (`kbq-skeleton`) con las clases BEM `c-skeleton-table`, `c-skeleton-table__header`, `c-skeleton-table__row` definidas en `scss/components/components/_c-skeleton.scss`.

<div class="c-skeleton-table" animate.enter="c-animate-in" animate.leave="c-animate-out">

== Patrones Observados

- Los componentes de formulario *no* tienen su propio `FormGroup`; usan `ControlContainer` para heredar el padre.
- Las opciones de selects se definen como arrays de `Option<T>` (interfaz en `core/utils/utils`).
- Los componentes compartidos usan `ChangeDetectionStrategy.OnPush` para rendimiento.
